# RuStore — что нужно для публикации

Готовое — отмечено ✅, за тобой — ⬜.

## 1. Сборка

✅ Флейвор `rustore`: `./tool/build_rustore.sh` → `app/dist/Fern-<версия>-rustore.apk`
✅ Один универсальный APK, а не сплиты и не AAB (см. «Почему APK» ниже)
✅ `REQUEST_INSTALL_PACKAGES` вырезано (`android/app/src/rustore/AndroidManifest.xml`), скрипт это проверяет
✅ `STORE=rustore`: свой апдейтер выключен, кнопка «Проверить обновления» из настроек убрана
✅ Подпись — наш `fern-release.jks`, тот же ключ, что у сборок с GitHub

### Почему APK, а не AAB

Бандл RuStore переподписывает своим ключом. Тогда версия из магазина
перестала бы вставать поверх версии с GitHub, и человеку пришлось бы удалять
приложение вместе с данными. С APK нашей подписью каналы совместимы в обе
стороны, и RuStore сам советует держать ту же подпись, что в других магазинах.

Плата за это — вес: 96 МБ против 56 МБ у сплита под arm64. Из сборки выброшен
`x86_64`, он стоил 52 МБ ради устройств, которых у людей нет.

Резали в три захода, и это стоит помнить. `ndk.abiFilters` во флейворе не
работает: плагин Flutter выставляет фильтры сам, из `--target-platform`, и
флейворные значения перетирает. Флаг `--target-platform` в одиночку убирает
только библиотеки Flutter, а нативные части плагинов (ML Kit, sqlite3) пакует
Gradle, и они остаются. Работает `androidComponents` с исключением
`lib/x86*/**` для варианта rustore, он и стоит в `build.gradle.kts`.

## 2. Монетизация: только ключ

⬜ Ничего настраивать не нужно, но помнить стоит.

Платёжные инструменты RuStore (платные приложения, подписки, встроенные
покупки) с 1 февраля 2026 работают только у ИП и юрлиц. У физлица платные
приложения скрывают с витрины, BillingClient SDK и Pay SDK перестают отвечать.

Сторонние платежи RuStore разрешает и комиссию за них не берёт. Поэтому в
RuStore-сборке Pro открывается ключом: оплата на lava.top, ключ выдаёт
@SnTAppsBot. Интерфейс тот же, что в GitHub-сборке (`_keyButtons` в
`lib/widgets/pro_sheet.dart`).

## 3. Карточка приложения

⬜ **Название:** `Fern — карточки для языков`
⬜ **Краткое описание:** `Красивые флеш-карточки: учи слова из книг, видео и фото. Офлайн, без аккаунта.`
⬜ **Полное описание:** копировать целиком из [`play/description-ru.txt`](play/description-ru.txt)
⬜ **Иконка 512×512:** [`play/icon-512.png`](play/icon-512.png)
⬜ **Скриншоты телефона** — минимум 4: главный экран с колодами, сессия повторов, читалка с тапом по слову, экран прогресса
⬜ **Категория:** Образование
⬜ **Возрастной рейтинг:** 3+ (насилия, азартных игр и пользовательского контента нет)
⬜ **Политика конфиденциальности:** https://thet1me-1.github.io/Fern/privacy.html

Полное описание вставлять из .txt-файла, не из markdown-чеклиста: при
копировании из таблиц и блоков текст склеивается, и автопроверка магазина
считает его нечитаемым. На этом Fern уже споткнулся в Google Play 22 июля 2026.

## 4. Разрешения и данные при загрузке версии

**Типы данных: 0 из 38.** Fern не собирает и не передаёт пользовательские
данные: словарь, статистика и настройки лежат на телефоне, аккаунта нет,
аналитики нет. Перевод слова уходит в выбранный человеком сервис (Google,
DeepL или собственный сервер) и содержит только само слово, без
идентификаторов. Если модератор спросит про сетевые обращения — отвечать так.

**Чувствительные разрешения**, форма просит пояснить три (готовый текст):

```
POST_NOTIFICATIONS — ежедневное напоминание о повторении карточек. Время
напоминания человек задаёт сам в настройках, отключается там же.

READ_EXTERNAL_STORAGE (только для Android 12 и ниже) и READ_MEDIA_IMAGES —
приложение открывает книги в форматах EPUB, FB2 и TXT из памяти устройства,
распознаёт текст со снимка страницы и восстанавливает резервную копию из
файла. Разрешение запрашивается в момент самого действия, читаются только
выбранные человеком файлы. Ни файлы, ни изображения на сервер не уходят,
обработка идёт на устройстве.
```

Из RuStore-сборки убраны два разрешения: `REQUEST_INSTALL_PACKAGES` (магазин
обновляет сам) и `com.android.vending.BILLING` (приезжало от плагина покупок
Google, здесь Pro открывается ключом). Оба вырезаны в
`android/app/src/rustore/AndroidManifest.xml`.

## 5. Ключ доступа к API

✅ Ключ создан в RuStore Консоли, лежит в секретах репозитория:
`RUSTORE_KEY_ID` и `RUSTORE_PRIVATE_KEY` (base64 от PKCS#8).

⬜ **Перевыпустить ключ** после первой удачной заливки: нынешний передавался в
переписке. В консоли это создать новый и удалить старый, затем обновить оба
секрета через `gh secret set`.

Проверить связку без сети и без загрузки:

```bash
cd app && python3 tool/rustore_upload.py --selftest
```

## 6. Первая публикация — руками

⬜ Приложение с `com.fern.app` создаётся в консоли: API не заводит карточку и
не принимает первую версию.
⬜ После первой версии загрузку берёт на себя workflow.

## 7. Как выходит новая версия

1. Поднять `version:` в `app/pubspec.yaml`, описать раздел в `CHANGELOG.md`
2. `git tag v1.18.2 && git push origin v1.18.2`
3. Job `rustore` собирает APK, проверяет подпись и заливает черновик через API
4. Версия уходит на модерацию (`publishType=MANUAL`)
5. **После проверки публикацию нажимаешь ты** в RuStore Консоли

`versionCode` общий с остальными каналами и обязан расти: магазин не примет
второй раз одно и то же число.

## 8. Что делает скрипт заливки

`app/tool/rustore_upload.py`, без зависимостей, подпись считает `openssl`.

| Шаг | Запрос |
|---|---|
| Авторизация | `POST /public/auth/`, подпись RSA-SHA512 от `keyId + timestamp`, токен живёт 15 минут |
| Черновик | `POST /public/v1/application/com.fern.app/version` → versionId |
| Файл | `POST .../version/{id}/apk?servicesType=Unknown&isMainApk=true` |
| Модерация | `POST .../version/{id}/commit` |

Подпись действительна минуту: если раннер или машина уехали по времени больше
чем на 60 секунд, авторизация вернёт ошибку.

Черновик на приложение может быть только один. Если предыдущая версия висит
неопубликованной, API откажет — черновик нужно опубликовать или удалить в
консоли, и скрипт это подскажет в тексте ошибки.
