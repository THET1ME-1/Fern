# Google Play — что нужно для публикации

Готовое — отмечено ✅, за тобой — ⬜.

## 1. Сборка

✅ Отдельный вариант для Play: `./tool/build_play.sh` → `app/dist/Fern-<версия>-play.aab`
✅ Из Play-сборки вырезано `REQUEST_INSTALL_PACKAGES` (скрипт это проверяет и падает, если разрешение вернулось)
✅ Обновления в Play-сборке идут через **Play In-App Update**, а не с GitHub
✅ targetSdk 36, нативные библиотеки выровнены под 16 КБ страниц
✅ Подпись постоянным ключом (`android/fern-release.jks`, копия в `~/keys/`)

✅ **Ключ Google НЕ отдаём — каналы разделены намеренно** (решено 2026-07-21).
Play подписывает приложение своим ключом (Play App Signing по умолчанию), с
GitHub идёт сборка под `fern-release.jks`. Подписи разные, поэтому версии из
двух каналов физически не встанут друг поверх друга — и не смешаются случайно.
Человек выбирает канал один раз: либо магазин, либо GitHub. Переход между
каналами возможен только через удаление приложения, поэтому **перед переходом
нужна резервная копия из настроек** — так и писать в описании, если спросят.

## 4. Data Safety (декларация данных)

Отвечать так:

| Вопрос | Ответ |
|---|---|
| Собирает ли приложение данные пользователя? | **Нет** |
| Передаёт ли данные третьим лицам? | **Нет** |
| Шифруется ли передача? | Да (HTTPS; обычный HTTP — только к серверу в локальной сети пользователя, если он сам его настроил) |
| Можно ли запросить удаление данных? | Данные не собираются; всё удаляется вместе с приложением или кнопкой «Удалить все данные» |

Важная оговорка: слова, которые пользователь переводит, уходят к выбранному им сервису перевода (Google, DeepL или его собственный сервер). Это не «сбор данных приложением», но если Google спросит про сетевые обращения — так и объясняй: запрос содержит только переводимое слово, без идентификаторов.

## 7. Что помнить про каналы

| | GitHub / Obtainium | Google Play | RuStore |
|---|---|---|---|
| Сборка | `./tool/build_release.sh` | `./tool/build_play.sh` | `./tool/build_rustore.sh` |
| Формат | APK по ABI | AAB | универсальный APK |
| Обновление | своё, с GitHub | Play In-App Update | магазин |
| Разрешение на установку APK | есть | вырезано | вырезано |
| Ключ подписи | `fern-release.jks` | ключ Google (Play App Signing) | `fern-release.jks` |
| Pro | ключ от бота | покупка в Play | ключ от бота |

Из-за общей подписи RuStore и GitHub взаимозаменяемы: версия из магазина
встаёт поверх версии с GitHub и наоборот. Play остаётся отдельным островом,
переход туда и обратно требует удаления приложения и резервной копии.
Подробности про RuStore — [`rustore-checklist.md`](rustore-checklist.md).

`versionCode` (число после `+` в pubspec) обязан расти при каждой загрузке в Play — Play не примет одинаковый дважды, даже если предыдущую сборку удалить.

## Ключи подписи

**Ключ загрузки (upload key)** — наш, лежит в `app/android/fern-release.jks`
(копия в `~/keys/`). Им подписываются AAB, которые уезжают в консоль. Потеряем —
потеряем возможность обновлять приложение в магазине.
Отпечаток SHA-256: `51:6E:FD:44:E8:AF:67:2B:A7:A9:B1:01:09:0D:B5:46:98:F5:BB:42:E1:09:C1:B0:0A:D4:AA:A5:2A:2C:E3:A1`

**Ключ подписи приложения (app signing key)** — у Google, приватная половина
недоступна никому. Им Play переподписывает то, что мы загрузили, и именно эти
отпечатки видят сторонние API (вход через Google, Maps, deep links):

| | |
|---|---|
| MD5 | `C7:7F:A4:BE:5D:D7:56:60:E0:52:DC:3F:27:9A:BB:0C` |
| SHA-1 | `9B:CB:2C:5A:7C:CC:72:50:59:5C:EC:43:10:56:F4:22:75:5F:0A:83` |
| SHA-256 | `9F:E3:3D:04:EF:C0:B2:20:DC:72:E6:23:47:58:02:6F:39:57:E7:EC:3E:13:ED:AE:F8:7F:21:EB:21:87:2D:E3` |

Fern сторонних API не использует, так что отпечатки нужны разве что для
`assetlinks.json`, если когда-нибудь появятся ссылки, открывающиеся приложением.
